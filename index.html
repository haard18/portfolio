Agents are easy to demo. Hard to run.

Six things I've had to actually get right, and where each one is running.

01 · Orchestration

Many agents, one shared context

Multi-step workflows where each agent gets a narrow tool surface and a typed contract instead of a wall of prompt. Shared context pipelines so step four knows what step one found, streaming so the user sees progress instead of a spinner, and checkpoints so a failure resumes rather than restarts.

Shipped in: Juriqa · Viral Pipeline
02 · Reliability

Treat the model as a flaky network call

Because that's what it is. Retries with backoff, idempotent tool calls, schema validation on every structured output, timeouts and token ceilings per run, and a dead-letter path for the ones that still fail. Same discipline as a trading relay — the model is just a slower, chattier upstream.

Learned in: Rust relay servers · NATS · MT5
03 · Evals

Know if today's prompt is worse

A fixed case set, graded runs, and a diff before anything ships. Traces captured per run so a bad output can be replayed instead of argued about. Vibes are not a regression test, and "it worked when I tried it" is not a deployment signal.

Tooling: tracekit · structured run logs
04 · Cost & models

Right model, smallest model

Frontier models for reasoning, cheap models for routing and extraction, and fine-tuned local models where the task is narrow and the volume is high. I built a toolchain that takes real agent traces and QLoRA-tunes a small model that runs offline on a laptop.

Open source: github.com/haard18/tracekit · 8.5M words → a 0.5B model that ships
05 · Product

I decide what to build, not just how

Sentio wasn't a ticket handed to me. I chose the problem, shaped it into two layers users could understand, wrote the positioning, shipped it, and went and got the partnerships. Same with tracekit: the hard call there was scoping it down — it does imitation SFT on your own traces, not frontier distillation, and the README says so loudly. Overclaiming is a product bug.

Owned: Sentio · tracekit · Vena
06 · Autonomy

Agents that run a function, not a prompt

Sentio's Sentinels sit on deployed contracts indefinitely, watch for anomalous behaviour, and escalate to a human only when something is actually wrong. Weatherbot trades on its own and stands down when expected value doesn't clear the bar. The hard part of autonomy is the not-acting — knowing when to stay quiet and when to wake someone up.

Running in: Sentio Sentinels · Weatherbot

01
tracekit: Traces → Your Own Local Model
Your coding agent already left training data on your laptop. tracekit mines those session logs, keeps only the edits that survived to a commit, and QLoRA-tunes a small model that runs offline. Eight-stage pipeline — scan, ingest, curate, build, train, eval, export, serve — with secret scrubbing, a reproducibility manifest, held-out evals, and an OpenAI-compatible endpoint that falls through to a frontier API only when it should.
8.5M words mined · Qwen2.5-Coder-0.5B · loss 2.90→0.93 · token acc 69%→87% · ~31% of edit calls routed locally · 67 tok/s on Metal · 80 tests passing
